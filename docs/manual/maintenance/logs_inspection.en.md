# Component Log Inspection

## 1 System Component Logs

The default JumpServer data persistence directory (`VOLUME_DIR`) is `/data/jumpserver`. Run the following command to find the directory configured for the current environment:

```bash
cat /opt/jumpserver/config/config.txt | grep VOLUME_DIR
```

The examples in this section use `/data/jumpserver/`.

Core JumpServer logs are stored in `/data/jumpserver/core/data/logs`.

**Core log files**

| Log file | Description |
| :--- | :--- |
| `ansible.log` | Logs generated by Ansible tasks, such as testing Linux asset connectivity, updating hardware information, pushing system users, and running secret change plans on Linux. |
| `beat.log` | Scheduled task logs. |
| `celery_ansible.log` | Task logs from the asynchronous Ansible queue. |
| `celery_default.log` | Task logs from the default asynchronous queue. |
| `celery.log` | Celery component logs. |
| `daphne.log` | Logs from the Django component that primarily supports WebSocket. |
| `drf_exception.log` | Exceptions raised by the DRF framework. |
| `flower.log` | Task monitoring component logs for Job Center. |
| `gunicorn.log` | Request logs. |
| `jumpserver.log` | Aggregate JumpServer logs. |
| `unexpected_exception.log` | JumpServer error logs. |

## 2 Inspect Docker Logs

**Example: follow the last 100 lines from the Core container**

```bash
docker logs -f jms_core --tail 100
```

**Follow logs from another component**

```bash
# By container ID
docker logs -f [Container ID]

# By container name
docker logs -f [Container name]
```

**Filter logs by time range**

```bash
# Logs from the last 30 minutes
docker logs --since 30m jms_core

# Logs generated after a specific time
docker logs --since "2026-07-21T10:00:00" jms_core

# Last 200 lines generated during the past hour
docker logs --since 1h --tail 200 jms_core
```

## 3 Change the Log Level

The `LOG_LEVEL` parameter in `config.txt` controls the default JumpServer log level. Supported values are `DEBUG`, `INFO`, `WARN`, and `ERROR`. When troubleshooting, you can temporarily set the level to `DEBUG` to collect more detailed logs.

**Procedure:**

1. Change the log level in `/opt/jumpserver/config/config.txt`:

    ```ini
    LOG_LEVEL=DEBUG
    ```

2. Restart JumpServer to apply the configuration:

    ```bash
    jmsctl restart
    ```

!!! warning "Attention"
    The `DEBUG` level generates a large volume of logs and consumes disk space more quickly. After troubleshooting, restore `LOG_LEVEL` to its previous value and restart the service.
