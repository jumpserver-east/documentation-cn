# System Architecture

## 1 Overview

JumpServer uses a microservice architecture. JumpServer services run in Docker, with different functional modules running in separate containers. Docker Compose and the `jmsctl` management script orchestrate the JumpServer services and maintain dependencies between functional modules.

!!! tip ""
    Enterprise package format: `jumpserver-ee-{{ jumpserver.tag }}-x86_64.tar.gz` [jumpserver-ee-system-version-system-architecture]

## 2 Dependent Components

JumpServer depends on the following components:

| Component | Description |
| :--- | :--- |
| jms_web | The high-performance HTTP and reverse proxy web server for JumpServer. |
| jms_core | The core JumpServer component. It primarily provides authentication and authorization services. |
| jms_celery | The JumpServer task scheduling server. |
| jms_koko | An asset connection component that provides command-line access to Linux, K8S, database, and other assets. |
| jms_lion | An asset connection component that provides access to Windows assets through the browser-based web terminal. |
| jms_chen | An asset connection component that provides access to databases through the browser-based web terminal. |
| jms_magnus | An asset connection component that uses a database proxy to let users connect directly to databases with native clients such as Navicat and DBeaver (X-PACK). |
| jms_razor | An asset connection component that uses the JumpServer client to launch the native MSTSC remote connection tool on a user's PC and access Windows assets. |
| jms_xrdp | An asset connection component that supports connections to and auditing of assets running older versions of Windows, such as Windows 2003. |
| jms_facelive | A component that enables MFA authentication through facial recognition. |
| jms_panda | A supporting component for the JumpServer Linux RemoteApp server. |
| jms_video | A component that converts session recordings to MP4. |
| jms_nec | A component that supports client-based connections to VNC assets. |
| PostgreSQL | Provides database services and stores core JumpServer data. If an external PostgreSQL service is not provided, JumpServer automatically runs the `jms_postgresql` container. |
| Redis | Provides database information caching. If an external Redis service is not provided, JumpServer automatically runs the `jms_redis` container. |

## 3 Directory Purposes

The JumpServer installation and configuration directory is `/opt/jumpserver`. The default data persistence directory (`VOLUME_DIR`) is `/data/jumpserver`. To find the persistence directory for the current environment, read the configuration file:

```bash
cat /opt/jumpserver/config/config.txt | grep VOLUME_DIR
```

**Main directories and their purposes:**

| Directory | Purpose |
| :--- | :--- |
| `/opt/jumpserver/config/` | Stores configuration for all components. The most important file is `config.txt`, which contains the core JumpServer configuration. |
| `$VOLUME_DIR/core/data/celery/` | Stores logs for asynchronous tasks in the Ansible queue. This directory has two levels of subdirectories selected from the first two characters of the task ID. Each log is named `ID.log`.<br>For example, for task ID:<br>`6a942d0a-52ab-4704-beae-137465ca3eca`<br>the log file is:<br>`6a942d0a-52ab-4704-beae-137465ca3eca.log`<br>and is stored in:<br>`$VOLUME_DIR/core/data/celery/6/a/`. |
| `$VOLUME_DIR/core/data/logs/` | Stores JumpServer logs:<br>- `ansible.log`: logs generated by Ansible automation tasks, such as testing asset connectivity, updating hardware information, pushing accounts, and running secret change plans.<br>- `beat.log`: scheduled task logs.<br>- `celery_ansible.log`: asynchronous Ansible queue task logs.<br>- `celery_default.log`: default asynchronous queue task logs.<br>- `celery.log`: Celery component logs.<br>- `daphne.log`: logs from the Django component that primarily supports WebSocket.<br>- `drf_exception.log`: exceptions raised by the DRF framework.<br>- `flower.log`: task monitoring logs for Job Center.<br>- `gunicorn.log`: API request logs.<br>- `jumpserver.log`: aggregate JumpServer logs.<br>- `unexpected_exception.log`: JumpServer error logs. |
| `$VOLUME_DIR/core/data/media/` | Stores RemoteApp source files, session recordings, uploaded and downloaded files, custom logos, and similar content. |
| `$VOLUME_DIR/core/data/ops/` | Stores playbook files uploaded by users. |
| `$VOLUME_DIR/core/data/static/` | Stores static files used by JumpServer at runtime, such as images, CSS, and JavaScript. |
| `$VOLUME_DIR/<component-name>/data/certs/` | Stores certificates required by the component. |
| `$VOLUME_DIR/<component-name>/data/ftp_files/` | Temporarily stores files uploaded or downloaded through the component. |
| `$VOLUME_DIR/<component-name>/data/keys/` | Stores the key used when the component registers with Core. |
| `$VOLUME_DIR/<component-name>/data/logs/` | Stores component logs. |
| `$VOLUME_DIR/<component-name>/data/replays/` | Stores session data being generated by the component. When the session ends, the recording is sent to Core. |
| `$VOLUME_DIR/db_backup` | Stores JumpServer database and configuration backups. |
| `$VOLUME_DIR/postgresql/` | Stores persistent data for the built-in PostgreSQL service. |
| `$VOLUME_DIR/redis/` | Stores configuration and persistent data for the built-in Redis service. |
